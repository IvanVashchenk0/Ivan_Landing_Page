### Pentimento asset preservation

`media-source/projects/pentimento/Textured_mesh_1.glb` is the single canonical copy of the supplied GLB (approximately 223 MiB). It has not been decimated, compressed, merged, or re-exported. `prepareCustomGLBShell()` adds the entire imported scene to one new parent group, records native bounds, and centers only that parent. Its scale remains 1; camera fitting handles the original authored dimensions. Child geometry, indices, UVs, normals, tangents, hierarchy, material references, texture transforms, and color-space settings are retained. The viewer uses no tone mapping or material normalization; lighting is configured separately. There is no shell-editing, substitution, or export workflow in this site.

Production selects the verified `pentimento.model-binary-repacked` derivative (181.05 MiB). Stage A removed base64 packaging only: every geometry accessor and embedded JPEG byte matches the canonical master. Both GLBs remain unchanged and separately registered.

An experimental mobile path selects `pentimento.model-mobile` only on phones, tablets, and touch-capable devices. The supplied 30,697,560-byte GLB remains byte-for-byte unchanged at SHA-256 `c3d000c498548b37e4e88cf81c0906da4321253e738dda57ffdd5cd0c08eaaed`. It has one scene, one node, one mesh, two indexed triangle primitives, 755,621 unique position vertices, 809,979 triangles, two unlit materials, and two embedded 1024×1024 JPEG textures. Mobile never requests the desktop GLB and never speculatively loads the mobile GLB; FINAL MODEL selection starts its viewer import and download.

The original `sarah_checkin.MOV` and prior H.264 `sarah_checkin.mp4` remain untouched. Production selects `sarah_checkin-web.mp4`: 1920×1080 H.264/yuv420p, 30 fps, muted audio removed, 5× acceleration baked into 19.50 seconds, and fast-start metadata. Runtime playback is 1×. Real video/model posters appear before playback or interactive rendering. Details, integrity hashes, benchmarks, and the mandatory upload-before-deployment sequence are in [conference preview delivery](pentimento-performance.md).

Initial homepage load does not request a GLB. On desktop, viewer code still warms at 1,200px and the interface mounts at 250px. At 30% visibility, automatic desktop raw-byte prefetch waits for stable video playback and adequate buffering, respecting Save-Data and constrained connection signals. Explicit desktop model hover, focus, pointer intent, or selection bypasses those automatic restrictions. A brief desktop WebGL2/8K capability probe avoids downloading a model that the device cannot support; it does not reduce model fidelity. Mobile performs no speculative model work and creates its single capped-DPR WebGL renderer only after explicit selection.
`modelLoader.ts` owns a single in-flight promise, throttled received-byte progress (at most about 8 updates/second), optional Content-Length, one retained completed ArrayBuffer, and Cache Storage `pentimento-assets-v1`. Percentages appear only with a usable unencoded Content-Length; otherwise only received MiB is shown. Download completion changes the restrained status to PREPARING INTERACTIVE MODEL while retaining the real still, yields briefly for that image/status to paint, then parses the already-fetched bytes and prepares the renderer. No scene parsing or full viewer initialization happens merely because bytes finish prefetching. The capability probe is short-lived and immediately released. Parsing and initial GPU upload can still temporarily occupy the main thread; this is not a worker-based/progressive model implementation.

The persistent cache stores the exact full GLB payload. Cache read/write/quota failures fall back to HTTP/session memory without blocking display. Known-length downloads fill one preallocated buffer; unknown-length responses consolidate chunks once and release them. Cache writes may temporarily hold another response body, but no second raw buffer is kept in application state. Failed partial transfers retry from the beginning; there is no fabricated resume support. Invalid GLB headers/lengths are rejected, and invalid persistent entries are removed before fetching afresh.

Once explicitly selected, download/preparation continues across input/model switches; the same parsed scene and canvas remain mounted. Scrolling away or hiding the tab pauses rendering without discarding bytes or scene state. An active prefetch continues across scroll changes to avoid restart churn. When the last Pentimento instance unmounts, its in-flight download is aborted; renderer, scene, controls, and observers are disposed. Completed raw bytes remain cached for the session and later route visits; parsed scenes are disposed on route exit and rebuilt only on another explicit selection. A zero-delay cleanup grace period avoids duplicate work from React Strict Mode's discarded setup.

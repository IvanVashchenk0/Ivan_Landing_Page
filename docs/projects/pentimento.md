### Pentimento asset preservation

`media-source/projects/pentimento/Textured_mesh_1.glb` is the single canonical copy of the supplied GLB (approximately 223 MiB). It has not been decimated, compressed, merged, or re-exported. `prepareCustomGLBShell()` adds the entire imported scene to one new parent group, records native bounds, and centers only that parent. Its scale remains 1; camera fitting handles the original authored dimensions. Child geometry, indices, UVs, normals, tangents, hierarchy, material references, texture transforms, and color-space settings are retained. The viewer uses no tone mapping or material normalization; lighting is configured separately. There is no shell-editing, substitution, or export workflow in this site.

The original `sarah_checkin.MOV` is HEVC. `media-source/projects/pentimento/sarah_checkin.mp4` is an H.264 browser-playback copy made with macOS `avconvert` at 1920×1080, retaining the original duration and using fast-start metadata. The original file remains untouched. Playback speed is applied at runtime, not baked into the video. Media paths and the adjustable speed live in `src/projects/pentimento/media.ts`.

The unchanged GLB is intentionally large. Initial homepage load does not request it. At 1,200px from the viewport, Pentimento UI and viewer/Three.js code warm in the background; the UI and input video still mount at the original 250px boundary. At 30% visibility, eligible connections begin raw-byte prefetch. Hover, focus, pointerdown, or a 2.5-second visible dwell also request the same shared stream. Save-Data and reported slow-2g/2g/3g connections suppress all automatic requests; explicit FINAL MODEL selection always works.

`modelLoader.ts` owns a single in-flight promise, throttled received-byte progress (at most about 8 updates/second), optional Content-Length, one retained completed ArrayBuffer, and Cache Storage `pentimento-assets-v1`. Percentages appear only with a usable unencoded Content-Length; otherwise only received MiB is shown. Download completion changes the UI to PREPARING RECONSTRUCTION, yields briefly for that message to paint, then parses the already-fetched bytes and prepares the renderer. No automatic parsing or WebGL initialization happens merely because bytes finish prefetching. Parsing and initial GPU upload can still temporarily occupy the main thread; this is not a worker-based/progressive model implementation.

The persistent cache stores the exact full GLB payload. Cache read/write/quota failures fall back to HTTP/session memory without blocking display. Known-length downloads fill one preallocated buffer; unknown-length responses consolidate chunks once and release them. Cache writes may temporarily hold another response body, but no second raw buffer is kept in application state. Failed partial transfers retry from the beginning; there is no fabricated resume support. Invalid GLB headers/lengths are rejected, and invalid persistent entries are removed before fetching afresh.

Once explicitly selected, download/preparation continues across input/model switches; the same parsed scene and canvas remain mounted. Scrolling away or hiding the tab pauses rendering without discarding bytes or scene state. Even weak prefetch continues across scroll changes to avoid restart churn. When the last Pentimento instance unmounts, its in-flight download is aborted; renderer, scene, controls, and observers are disposed. Completed raw bytes remain cached for the session and later route visits; parsed scenes are disposed on route exit and rebuilt only on another explicit selection. A zero-delay cleanup grace period avoids duplicate work from React Strict Mode's discarded setup.
